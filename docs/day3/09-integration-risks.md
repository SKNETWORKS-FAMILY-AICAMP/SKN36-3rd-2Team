## 4. 잔여 위험 목록

### RISK-01. 실제 콘텐츠 정본 미승인

- **등급:** P0
- **현황:** 테스트용 콘텐츠와 별개로 실제 StoryEvent 정본 승인 절차가 필요합니다.
- **영향:** 실제 게임에서 신규 스토리 이벤트가 표시되지 않을 수 있습니다.
- **대응:** 이벤트별 근거 문서, 트리거, 공개 조건, 엔딩 관련 여부를 검토합니다.
- **완료 기준:** 승인된 이벤트만 런타임에 등록되며 미승인 이벤트는 계속 차단됩니다.

### RISK-02. 실제 게임 행동과 이벤트 큐 연동 미완료

- **등급:** P1
- **현황:** 이벤트 큐 및 전달 API는 있지만 실제 게임 행동과 모든 이벤트의 연결은 완료되지 않았습니다.
- **영향:** 증거를 획득하더라도 스토리 이벤트가 자동으로 실행되지 않을 수 있습니다.
- **대응:** 증거 수집, NPC 대화, 챕터 전환과 이벤트 큐를 연결합니다.
- **완료 기준:** 승인된 테스트 시나리오에서 게임 행동 → 큐 등록 → 이벤트 조회 → ACK까지 동작합니다.

### RISK-03. 독립 프로세스 네트워크 E2E 미검증

- **등급:** P1
- **현황:** Django 테스트 클라이언트와 HTTP MockTransport 검증은 완료했습니다.
- **영향:** 실제 실행 시 서버 URL, 포트, 서비스 토큰, 연결 문제가 발생할 수 있습니다.
- **대응:** Django와 FastAPI를 독립 프로세스로 실행하고 실제 HTTP 요청을 검증합니다.
- **완료 기준:** 실제 서버 간 콘텐츠 조회 및 장애 처리 시나리오가 통과합니다.

### RISK-04. 운영 환경 Migration 미검증

- **등급:** P1
- **현황:** Migration 파일의 일치 여부는 검증했지만 운영 DB 적용은 검증하지 않았습니다.
- **영향:** 기존 DB에서 필드 누락 또는 데이터 호환성 문제가 발생할 수 있습니다.
- **대응:** 백업 후 스테이징 DB에서 Migration을 적용하고 데이터 정합성을 검증합니다.
- **완료 기준:** 스테이징 환경 적용 및 복구 절차 검증 완료.

### RISK-05. 서비스 인증 토큰 관리

- **등급:** P0
- **현황:** Django 내부 API는 서비스 토큰을 사용합니다.
- **영향:** 토큰 노출 시 내부 콘텐츠 API에 대한 비인가 접근 위험이 발생합니다.
- **대응:** 환경변수 또는 비밀값 관리 서비스를 사용하고 Git 추적을 금지합니다.
- **완료 기준:** 비밀값이 저장소와 프론트엔드 빌드 결과물에 포함되지 않습니다.

### RISK-06. 콘텐츠 공개 정책 불일치

- **등급:** P0
- **현황:** Django 런타임 승인과 FastAPI 플레이어 해금 정책이 별도로 존재합니다.
- **영향:** 잘못된 연결 시 미해금 증거나 스토리 정보가 조기 공개될 수 있습니다.
- **대응:** 두 시스템의 조건을 모두 검증하고 미승인 상태에서는 기본 거부합니다.
- **완료 기준:** 실제 정본 전체를 대상으로 공개 단계별 스포일러 검사가 통과합니다.

### RISK-07. Django 서비스 장애

- **등급:** P1
- **현황:** 연결 실패 및 타임아웃 처리 테스트는 통과했습니다.
- **영향:** Django 장애 중 신규 콘텐츠 조회가 실패할 수 있습니다.
- **대응:** 서비스 상태 모니터링, 타임아웃 및 운영 장애 대응 절차를 마련합니다.
- **완료 기준:** 장애 시 정보 유출 없이 오류를 반환하고 복구 후 정상 조회됩니다.

### RISK-08. 이벤트 중복 처리 및 상태 충돌

- **등급:** P1
- **현황:** SQLite revision CAS와 ACK 멱등 처리 테스트가 통과했습니다.
- **영향:** 실제 동시 요청과 서버 재시작 환경에서 추가 문제가 발생할 수 있습니다.
- **대응:** 재시작 및 동시 요청을 포함한 실제 통합 테스트를 수행합니다.
- **완료 기준:** ACK 누락·중복 없이 GameState가 유지됩니다.

### RISK-09. Django 콘텐츠 DB와 게임 상태 DB 간 버전 불일치

- **등급:** P1
- **현황:** 콘텐츠 정의와 플레이어 상태는 별도 DB에 저장됩니다.
- **영향:** 콘텐츠 버전 변경 시 기존 세션의 이벤트 ID와 새 콘텐츠가 불일치할 수 있습니다.
- **대응:** 콘텐츠 버전 고정 또는 세션별 버전 연결 정책을 설계합니다.
- **완료 기준:** 콘텐츠 변경 이후에도 기존 세션의 진행 상태가 일관되게 유지됩니다.

### RISK-10. StoryEvent 지원 트리거 범위 제한

- **등급:** P1
- **현황:** ORM에는 여러 트리거 유형이 정의되어 있지만, 승인 이벤트 API의 현재 계약은 `EVIDENCE_COLLECTED`에 제한됩니다.
- **영향:** NPC 해금, 챕터 시작, 대화 완료 기반 이벤트를 동일 방식으로 사용할 수 없습니다.
- **대응:** 트리거별 공개 규칙과 FastAPI 처리기를 단계적으로 확장합니다.
- **완료 기준:** 추가 트리거가 독립 테스트 및 전체 회귀 테스트를 통과합니다.

### RISK-11. 실제 UI·게임 플레이 검증 부족

- **등급:** P1
- **현황:** React 빌드 및 스포일러 검사에 통과했습니다.
- **영향:** 브라우저에서의 화면 표시, 새로고침, 중복 클릭, 세션 종료 등의 문제가 남아 있을 수 있습니다.
- **대응:** 실제 브라우저 기반 플레이 테스트를 수행합니다.
- **완료 기준:** 이벤트 표시·ACK·재접속·세션 변경 시나리오가 정상 동작합니다.

### RISK-12. Multi-Agent 및 MCP 통합

- **등급:** P1
- **현황:** Day 3의 범위에 포함되지 않았습니다.
- **영향:** 후속 기능 구현 시 기존 API와 상태 모델을 변경해야 할 수 있습니다.
- **대응:** 게임 상태 변경 권한과 콘텐츠 조회 권한을 에이전트별로 분리합니다.
- **완료 기준:** 에이전트 및 MCP 도구가 기존 공개 정책을 우회하지 않고 통합 테스트를 통과합니다.

이 항목들을 완료한 뒤 Multi-Agent와 MCP를 연동하여 게임의 동적 추론 및 상호작용 기능을 확장할 수 있습니다.
