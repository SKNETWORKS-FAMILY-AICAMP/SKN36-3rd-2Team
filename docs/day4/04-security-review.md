# Day 4 — Multi-Agent 및 MCP 보안 검토

## 1. 목적

Multi-Agent 및 MCP 도입으로 추가된 실행 경계에서 인증, 접근 제어, 게임 상태 무결성, 미공개 콘텐츠 노출 위험을 점검합니다.

검토 기준일: 2026-11-23

관련 이슈: #129~#135

## 2. 주요 신뢰 경계

| 경계 | 신뢰할 수 있는 정보 |
|---|---|
| 브라우저 → FastAPI | 서버가 검증한 요청만 |
| FastAPI → SQLite | 서버가 조회한 GameState |
| FastAPI → Agent | 검증된 AgentContext |
| FastAPI → MCP | 인증 후 생성한 BoundMCPContext |
| MCP → Django | 승인된 콘텐츠 및 선행 조건 |
| Hybrid RAG → 사용자 | 접근 정책과 원본 검증을 통과한 결과 |

LLM 출력, 사용자 프롬프트, 검색 결과의 임의 메타데이터는 권한 부여의 근거로 사용하지 않습니다.

## 4. 세션 및 인증

### 적용 방식

FastAPI는 기존 HMAC 기반 소유권 쿠키를 검증합니다.

MCP Server는 다음 순서로 생성합니다.

1. FastAPI 요청의 게임 세션 확인
2. HMAC 쿠키 검증
3. SQLite GameState 조회
4. 현재 NPC 선택과 revision 검증
5. 서버 검증 컨텍스트 생성
6. 세션 전용 MCP Server 구성

MCP Tool 입력으로 세션 ID나 인증 토큰을 받지 않습니다.

### 검증 결과

- 정상 플레이어: 접근 허용
- 인증 쿠키 없음: 접근 거부
- 다른 플레이어의 세션: 접근 거부
- 오래된 revision: 접근 거부

## 5. 증거 및 NPC 지식 접근 제어

### 증거 검색

`search_authorized_evidence`는 다음 조건을 확인합니다.

- 플레이어가 해당 증거를 획득했는가
- 검색 문서가 허용된 증거 문서인가
- 문서가 엔딩 전용 또는 보호된 사실을 포함하는가
- 검색 청크가 신뢰할 수 있는 원본에 존재하는가
- Django가 증거의 공개를 승인했는가
- 선행 증거 조건이 충족됐는가
- 결과 반환 직전 GameState가 유효한가

### NPC 지식

`get_npc_knowledge`는 다음 조건을 확인합니다.

- 서버가 검증한 현재 NPC인가
- NPC가 해금됐는가
- Django가 해당 카드를 승인했는가
- 승인 내용과 서버 원본이 일치하는가
- 게임 접근 정책을 충족하는가

Django 장애 또는 승인 검증 실패 시 콘텐츠 공개를 차단합니다.

## 6. 프롬프트 인젝션 대응

### 검증한 시나리오

사용자 입력에 시스템 지침 무시와 비공개 증거 공개를 요구하는 문장을 넣어 테스트했습니다.

관측 결과:
- Hint Agent가 미획득 증거를 근거로 반환하지 않음
- Deduction Agent가 미획득 증거 ID 요청을 거부함
- MCP 게임 상태 및 증거 목록이 허용 범위를 유지함

### 제한사항

위 결과는 현재 규칙 기반 로직에 대한 자동화 테스트입니다.

실제 외부 LLM의 복잡한 프롬프트 인젝션, 검색 문서 내 악성 지침, 다중 턴 공격에 대한 포괄적인 방어 성능을 의미하지 않습니다.

## 7. 게임 상태 무결성

### 읽기 전용 경로

Deduction·Hint Agent는 실행 전후 저장 상태를 검사합니다.

MCP Tool은 바인딩된 상태 스냅샷을 사용하며 최신 상태를 다시 조회합니다.

### 상태 변경 경로

NPC Agent는 기존 원자적 대화 처리 경로를 사용합니다.

게임 진행 상태 변경은 서버의 명시된 게임 서비스에서 관리합니다.

### 동시성 검증

SQLite revision을 변경한 뒤 기존 AgentContext와 BoundMCPContext로 실행하면 두 경로 모두 요청을 거부하는 테스트를 통과했습니다.

### 추가 검토 필요 사항

현재 MCP Tool은 게임 상태 및 콘텐츠 접근 정책으로 반환 데이터를 제한하지만, **NPC·Deduction·Hint Agent별 Tool 호출 권한을 MCP Server가 별도로 강제하지는 않습니다.**

또한 MCP Server가 외부 HTTP 경로에 등록되지 않았다는 사실은 확인했으나, 내부 호출자의 신뢰 경계는 향후 Agent–Tool 실행 구조 확장 시 재검토해야 합니다.
