## 2. 작업 배경

기존 프론트엔드에서는 현장 조사 장소와 세부 공간을
정적 데이터로 관리하고 있었다.

백엔드에는 챕터 해금, 증거 획득, 조사 Action에 대한
권한 검증 기능이 구현되어 있었지만, 장소별 접근 가능
상태를 일괄 조회하는 API는 제공하지 않았다.

이에 따라 프론트엔드에서 조사 장소와 조사 버튼의
활성화 여부를 서버 상태와 동기화하기 어려웠다.

이번 작업에서는 장소 접근과 실제 증거 획득 권한을
분리하고 기존 서버 권한 정책을 재사용하는
읽기 전용 장소 조회 API를 구현하였다.

## 3. 작업 목적

- 현장 조사 장소 7곳의 접근 상태 제공
- 세부 공간 5곳의 접근 상태 제공
- 기존 프론트엔드 조사 Action 9개 연동
- 챕터 및 선행 증거에 따른 조사 가능 상태 제공
- 기존 조사 권한 검증 로직 재사용
- 콘텐츠 승인 정책 유지
- 미공개 조사 Action 및 보호 정보 노출 방지
- 조회 요청에 의한 게임 상태 변경 방지

## 4. 신규 API 명세

### 4.1 요청

    GET /api/games/{session_id}/locations

별도의 요청 본문이나 Query Parameter는 필요하지 않다.

기존 게임 세션 소유권 확인용 쿠키를 전달해야 한다.

### 4.2 응답 예시

    {
      "currentChapter": "CH01",
      "revision": 12,
      "locations": [
        {
          "id": "lobby",
          "accessible": true,
          "actions": [],
          "subspaces": [
            {
              "id": "desk",
              "accessible": true,
              "actions": [
                {
                  "actionId": "inspect-e19-a",
                  "available": true
                },
                {
                  "actionId": "inspect-e21-a",
                  "available": false
                }
              ]
            },
            {
              "id": "corridor",
              "accessible": true,
              "actions": []
            }
          ]
        }
      ]
    }

위 응답은 일부 장소만 포함한 설명용 예시이다.
실제 API는 전체 장소 7곳을 반환한다.

### 4.3 응답 필드

| 필드 | 자료형 | 설명 |
|---|---|---|
| currentChapter | 문자열 | 현재 챕터 |
| revision | 정수 | 현재 게임 상태 버전 |
| locations | 배열 | 공개 장소 목록 |
| locations[].id | 문자열 | 프론트엔드 장소 ID |
| locations[].accessible | 불리언 | 장소 접근 가능 여부 |
| locations[].actions | 배열 | 장소에 연결된 조사 Action |
| locations[].subspaces | 배열 | 세부 공간 목록 |
| subspaces[].id | 문자열 | 세부 공간 ID |
| subspaces[].accessible | 불리언 | 세부 공간 접근 가능 여부 |
| subspaces[].actions | 배열 | 세부 공간의 조사 Action |
| actions[].actionId | 문자열 | 조사 Action ID |
| actions[].available | 불리언 | 조회 시점의 조사 가능 여부 |

### 4.4 캐시 정책

정상 응답에는 다음 헤더를 적용한다.

    Cache-Control: private, no-store

플레이어별 조사 상태가 공유 캐시에 저장되지 않도록 한다.

## 7. 접근 권한 정책

### 7.1 공개 장소 접근

다음 조건을 충족하는 경우 공개 장소와 세부 공간의
접근 상태를 활성화한다.

- 확장 콘텐츠 버전 사용
- 현재 게임 단계가 수사 단계
- 게임이 종료되지 않은 상태
- 프롤로그가 아닌 조사 챕터
- 현재 챕터가 해금된 상태

장소에 접근할 수 있다는 사실은 해당 장소에서
증거를 획득할 수 있다는 의미가 아니다.

현재 구현은 공개 배경 공간에 공통 접근 조건을 적용한다.
장소별 독립적인 스토리 해금 정책은 확정 이후 추가한다.

### 7.2 조사 Action 접근

기존 조사 검증 함수를 공통으로 사용한다.

주요 검증 항목:

- 게임 세션 소유권
- 게임 진행 상태
- Action 승인 여부
- 현재 챕터와 Action의 챕터 일치 여부
- 챕터 해금 여부
- 필수 플래그
- 선행 증거
- 증거 획득 경로
- NPC 선택 상태
- Django 장면 승인
- Django 증거 공개 조건
- 보호 콘텐츠 접근 정책

조회 결과는 현재 시점의 조사 가능 상태를 나타낸다.

실제 증거 획득 요청에서는 기존 POST API가
모든 권한 및 상태 조건을 다시 검증한다.

수행하지 않는다.

## 9. 기존 조사 API와의 관계

기존 API 경로는 유지한다.

    POST /api/games/{session_id}/investigations/{action_id}

요청 예시:

    {
      "expectedRevision": 12
    }

기존 POST API의 응답 계약, 원자적 증거 획득,
중복 획득 방지 및 점수 처리 로직은 유지한다.

신규 장소 API와 기존 조사 API는 공통 권한 검증
함수인 prepare_investigation_action을 사용한다.

## 10. HTTP 상태 코드

| 상태 코드 | 설명 |
|---|---|
| 200 | 장소 및 조사 가능 상태 조회 성공 |
| 404 | 게임 세션 없음 또는 소유권 불일치 |
| 409 | 조회 도중 게임 상태가 변경됨 |
| 503 | 콘텐츠 또는 증거 검증 서비스 사용 불가 |

장소 또는 개별 Action의 접근 권한 미충족은
정상 조회 응답의 false 값으로 표현한다.

외부 서비스 장애는 정상적인 잠금 상태와 구분한다.

## 15. 프론트엔드 연동 방법

### 15.1 장소 화면 진입

1. 장소 조회 API를 호출한다.
2. 응답의 revision과 currentChapter를 확인한다.
3. 장소 ID를 기존 fieldPlaces 정의와 연결한다.
4. 세부 공간 ID를 기존 fieldSubviews 정의와 연결한다.
5. accessible 값에 따라 장소 진입 버튼을 처리한다.
6. available 값에 따라 조사 버튼을 처리한다.

### 15.2 조사 완료 이후

1. 기존 현장 조사 POST API를 호출한다.
2. 최신 expectedRevision을 전달한다.
3. 조사 결과와 게임 상태를 갱신한다.
4. 장소 조회 API를 다시 호출한다.
5. 새롭게 활성화된 조사 Action을 화면에 반영한다.

### 15.3 재조회 시점

- 프롤로그 완료
- 챕터 이동
- NPC 선택 변경
- 증거 획득
- 추론 성공
- 게임 세션 복원
- 게임 상태 충돌 발생

장소 조회 결과는 실제 조사 성공을 보장하지 않는다.

조회 이후 게임 상태나 콘텐츠 승인 상태가 변경될 수
있으므로 실제 조사 결과는 POST 응답을 기준으로 한다.

## 17. 제한사항 및 후속 작업

- 정식 스토리 기반 장소별 독립 해금 정책은 미확정이다.
- 공개 배경 공간에는 공통 접근 정책을 적용하였다.
- 현장 UI 미연결 Action 13개의 장소 매핑은 별도 협의가 필요하다.
- 실제 Django 승인 서버 연동 검증이 필요하다.
- 장소 조회 시 기존 콘텐츠 서비스 검증을 재사용하므로
  반복 호출에 따른 응답 지연 및 서비스 부하를 확인해야 한다.
- 실제 프론트엔드 연동과 자연 플레이 검증은 후속 진행한다.
- 이번 작업은 프론트엔드 코드를 수정하지 않았다.

## 18. 최종 결과

현장 조사 장소 및 세부 공간의 접근 상태를 제공하는
읽기 전용 API를 추가하였다.

기존 조사 권한 정책을 재사용하여 장소 접근과
실제 증거 획득 권한을 분리하였다.

공개 장소 7곳, 세부 공간 5곳, 기존 UI 조사 Action
9개에 대한 응답 계약을 구성하였다.

신규 테스트 13건이 추가되었으며 전체 백엔드 회귀
테스트는 3174건 통과, 실패 0건, 제외 26건이다.
