## 2. 작업 배경

이슈 #212의 현장 조사 및 챕터 진행 통합 검증 과정에서
확장판 NPC 초기 공개 정책 누락 문제를 발견하였다.

기존 확장판 런타임에서는 이전 콘텐츠의 NPC 해금
규칙을 의도적으로 비활성화하고 있었다.

그러나 확장판 전용 NPC 공개 정책이 연결되지 않아
초기 NPC C01만 접근할 수 있었다.

이에 따라 특정 NPC와의 대화 및 조사가 필요한
핵심 증거 획득 경로에 차단 위험이 발생하였다.

특히 E28은 CH04 진입 필수 증거이므로 해당 문제는
최종 게임 진행을 막을 수 있는 문제였다.

## 3. 스토리 정본 확인

스토리 담당자 확인을 통해 다음 정책을 확정하였다.

### 3.1 장면별 근거

| 장면 | 확인 내용 |
|---|---|
| SC-0003 | 사건 직전 로비에 NPC 10명 등장 |
| SC-0004 | 열 사람의 진술을 조사해야 한다는 내레이션 |
| SC-0101 | NPC 10명의 프로필과 질문 기능 공개 |
| NPC 지식 카드 | 각 NPC의 신분 정보는 처음부터 공개 |

SC-0101의 세 사람 이상 진술 수집 조건은 NPC 해금
조건이 아니라 모순 표시 기능의 공개 조건이다.

증거 제시 조건은 NPC 자체의 해금 여부가 아닌
진술 단계 및 정보 공개 범위를 결정한다.

### 3.2 최종 확정 정책

| 항목 | 정책 |
|---|---|
| CH01 진입 | NPC 10명 전체 공개 |
| 챕터별 추가 해금 | 없음 |
| 증거 기반 추가 해금 | 없음 |
| 분기 재방문 | 공개 NPC 유지 |
| 증거 제시 | 진술 및 정보 공개 조건으로 사용 |
| 프로필 공개 | 공적 직함 중심 |
| 모순 표시 | 세 사람 이상의 진술 수집 조건 |

CH00에서는 기존 C01 초기 상태를 유지한다.

## 5. 시스템 설계

NPC 접근 권한과 정보 공개 권한을 분리한다.

    챕터 진입 요청
          |
          v
    세션 소유권 검증
          |
          v
    Revision 검증
          |
          v
    챕터 해금 조건 검증
          |
          v
    확장판 콘텐츠 여부 확인
          |
          v
    NPC 10명 공개 상태 구성
          |
          v
    SQLite 원자적 상태 저장
          |
          v
    GameResponse 및 공개 이벤트 반환

NPC 공개 이후에도 대화 요청은 기존 권한 정책을
통과해야 한다.

    NPC 선택
          |
          v
    세션 및 접근 권한 검증
          |
          v
    증거 제시 권한 검증
          |
          v
    NPC 진술 및 RAG 접근 정책
          |
          v
    허용된 정보만 응답

NPC 선택 가능 여부는 비공개 정보 열람 권한을
의미하지 않는다.

## 6. 핵심 구현

### 6.1 챕터 진행 엔진

변경 파일:

    backend/src/crimescene/scenario/chapter_progress.py

확장판 NPC 공개 식별자를 정의한다.

    EXPANDED_PUBLIC_NPC_IDS = tuple(
        f"C{i:02d}" for i in range(1, 11)
    )

확장판 콘텐츠가 CH01~CH04에 정상 진입하면
NPC 전체 공개 목록을 GameState에 반영한다.

기존 콘텐츠의 NPC 해금 상태는 변경하지 않는다.

### 6.2 원자적 상태 저장

챕터 전환과 NPC 공개 상태를 하나의 GameState로 구성한다.

기존 SQLite 트랜잭션을 재사용하여 다음 데이터를
일관성 있게 관리한다.

- 현재 챕터
- 해금된 챕터 목록
- 공개 NPC 목록
- 현재 선택 NPC
- Revision
- 기존 획득 증거
- 기존 수집 점수
- 기존 정보 공개 권한

별도의 데이터베이스 스키마 변경은 수행하지 않는다.

### 6.3 공개 이벤트 처리

변경 파일:

    backend/src/crimescene/api/app.py

챕터 전환 이전과 이후의 NPC 목록을 비교한다.

새롭게 공개된 NPC에 대해서만 NPC_UNLOCKED 이벤트를
생성한다.

최초 CH01 진입 시 C02~C10의 공개 이벤트 9개를 반환한다.

이후 챕터 전환 및 재방문에서는 중복 이벤트를
생성하지 않는다.

## 7. API 계약

### 7.1 챕터 진입

    POST /api/games/{session_id}/chapter/advance

요청 예시:

    {
      "expectedRevision": 1,
      "targetChapter": "CH01"
    }

응답 일부 예시:

    {
      "currentChapter": "CH01",
      "unlockedCharacters": [
        "C01", "C02", "C03", "C04", "C05",
        "C06", "C07", "C08", "C09", "C10"
      ],
      "events": [
        {
          "type": "CHAPTER_CHANGED",
          "chapter": "CH01"
        },
        {
          "type": "NPC_UNLOCKED",
          "characterId": "C02"
        }
      ]
    }

위 응답은 설명을 위해 일부 필드와 이벤트만 표시하였다.

실제 최초 진입 응답에는 신규 공개 이벤트 9개와
GAME_PROGRESS_UPDATED 이벤트가 포함된다.

기존 GameResponse 필드 및 자료형은 유지한다.

### 7.2 NPC 선택

    POST /api/games/{session_id}/characters/{character_id}/select

CH01 진입 이후 C01~C10을 모두 선택할 수 있다.

| 조건 | 응답 |
|---|---|
| 정상 공개 NPC 선택 | HTTP 200 |
| 프롤로그 조사 요청 | HTTP 409 |
| 존재하지 않는 NPC ID | HTTP 422 |
| 다른 세션 접근 | 기존 소유권 정책 적용 |

### 7.3 프론트엔드 연동

프론트엔드는 기존 unlockedCharacters 배열을 사용한다.

별도의 NPC 공개 규칙을 프론트엔드에 추가할 필요가 없다.

챕터 진입 성공 후 최신 GameResponse를 반영하고
NPC_UNLOCKED 이벤트를 기존 알림 처리에 전달한다.

## 8. 보안 검토

| 검토 항목 | 결과 |
|---|---|
| NPC 전체 공개 | 정상 |
| 미수집 증거 제시 | HTTP 403 |
| NPC 공개 시 증거 자동 지급 | 없음 |
| NPC 공개 시 점수 증가 | 없음 |
| NPC 공개 시 문서 권한 변경 | 없음 |
| NPC 공개 시 지식 카드 자동 공개 | 없음 |
| 기존 플래그 임의 추가 | 없음 |
| 중복 NPC 공개 이벤트 | 방지 |
| 기존 콘텐츠 해금 정책 | 유지 |
| RAG 보안 회귀 테스트 | 통과 |

NPC 공개 정책 변경으로 보호 증거의 접근 규칙,
기존 정책 평가 엔진 및 RAG 공개 조건을 변경하지 않았다.

실제 RAG 응답의 전체 보안 검증은 배포 환경에서
별도로 수행해야 한다.

## 11. 기존 저장 세션 호환성

| 기존 세션 상태 | 처리 |
|---|---|
| CH00 | CH01 진입 시 정상화 |
| CH01 | 다음 챕터 진입 시 정상화 |
| CH02 또는 CH03 | 챕터 전환 및 재방문 시 정상화 |
| CH04 | 별도 복구 필요 |
| 이전 콘텐츠 | 기존 정책 유지 |

기존 게임 데이터를 강제로 삭제하거나 수정하지 않는다.

기존 확장판 세션은 정상적인 챕터 전환 시 NPC 공개
목록이 자동으로 정상화된다.

챕터 전환 없이 머물러 있는 기존 세션의 즉시 복구는
현재 구현 범위에 포함하지 않는다.

## 13. 제한사항 및 후속 작업

- 기존 확장판 저장 세션의 즉시 복구는 별도 검토한다.
- 실제 NPC 대화 기반 E15, E16, E28 획득은 후속 검증한다.
- 최종 챕터 및 엔딩까지의 자연 플레이를 추가 검증한다.
- 실제 Qdrant, Ollama, Neo4j, Django 통합 환경을 검증한다.
- 세 사람 이상 진술 수집 조건은 모순 표시 기능 작업에서 검토한다.
- 실제 프론트엔드 알림 및 NPC 목록 갱신을 확인한다.

## 14. 최종 결과

스토리 정본에 따른 확장판 NPC 초기 공개 정책을 구현하였다.

CH01 진입 이후 NPC 10명에 대한 접근이 가능하며
기존 증거 및 정보 공개 정책을 유지한다.

신규 테스트 5건을 추가하였으며 전체 백엔드 회귀
테스트 3186건이 통과하였다.

NPC 접근 차단으로 인한 신규 게임의 진행 문제를
해결하였다.

실제 핵심 증거 획득 및 최종 엔딩까지의 자연 플레이
검증은 별도 통합 테스트에서 수행한다.
