## 2. 작업 배경

기존 수사 목표 API는 objectiveId와 status만 반환하였다.

프론트엔드에서는 상세 목표 문구를 서버로부터
받을 수 없어 모든 목표에 동일한 기본 안내를
표시하고 있었다.

기존 안내 문구:

    현재 공개된 자료와 인물을 조사하세요.

목표별 조사 방향을 플레이어에게 전달하기 위해
서버에서 제목 및 상세 설명을 제공하도록 개선하였다.

## 3. 콘텐츠 원본 분석

원본 파일:

    12_OBJECTIVES_AND_HINTS.csv

전체 수사 목표는 25개이며 기존 공개 대상으로
선정된 목표는 11개이다.

원본 CSV의 주요 필드는 다음과 같다.

| 필드 | 역할 |
|---|---|
| objective_id | 목표 식별자 |
| unlocked_by_evidence | 선행 증거 |
| target_evidence | 목표 증거 |
| chapter | 관련 챕터 |
| player_goal | 플레이어 조사 목표 |
| trigger_source | 목표 발생 조건 |
| hint_1 | 1단계 힌트 |
| hint_2 | 2단계 힌트 |
| hint_3 | 3단계 힌트 |
| wrong_feedback | 잘못된 조사 안내 |
| completion | 완료 조건 |
| status | 콘텐츠 작성 상태 |

원본 목표에는 미수집 증거 번호와 상세 획득 방법이
포함되어 있어 그대로 반환하지 않는다.

공개 대상으로 선정된 11개 목표에 대하여
스포일러를 제거한 별도의 표시 문구를 구성하였다.

## 6. 수사 목표 표시 문구

| 목표 ID | 제목 | 상세 설명 |
|---|---|---|
| OBJ_FIND_STUDENT_RECORD | 학생 기록 조사 | 사진에서 지워진 이름과 관련된 학생 기록을 확인하세요. |
| OBJ_CHECK_SCHOLARSHIP | 장학금 기록 대조 | 확보한 회람 자료를 장학금 수령 기록과 비교하세요. |
| OBJ_CHECK_SIGNOFF | 학적 변경 승인 확인 | 관련 승인 기록의 서명과 날짜를 확인하세요. |
| OBJ_TALK_SEOMIRAN | 학적 변경 경위 조사 | 서미란에게 2016년 학적 변경 경위를 질문하세요. |
| OBJ_CHECK_2016_VIDEO | 과거 영상 자료 조사 | 2016년 행사 당시의 촬영 자료를 확인하세요. |
| OBJ_VERIFY_DEPARTURE | 당시 이탈 경위 조사 | 확보한 자료를 토대로 이후의 이동 경위를 확인하세요. |
| OBJ_CHECK_DRAFT_EMAIL | 신기범의 일정 확인 | 신기범이 남긴 일정과 메일 관련 자료를 조사하세요. |
| OBJ_FIND_CARD_USER | 임시 카드 사용자 조사 | 카드 사용 기록과 다른 자료를 비교해 사용자를 좁혀 보세요. |
| OBJ_FIND_SHUTDOWN_REASON | CCTV 중단 원인 조사 | CCTV가 중단된 이유를 관련 기록을 통해 확인하세요. |
| OBJ_RECONSTRUCT_ROUTE | 사건 당시 동선 재구성 | 계단 주변의 이동 시각과 경로를 비교하세요. |
| OBJ_CHECK_REFLECTION | 사진 속 인물 조사 | 사진에 비친 인물의 알리바이를 확인하세요. |

표시 문구는 원본 player_goal을 기준으로
플레이어가 확인할 수 있는 범위로 재작성하였다.

미공개 증거 번호와 세부 획득 방법은 제거하였다.

원본 목표의 작성 상태가 초안이므로
최종 문구에 대한 콘텐츠 담당자 검토가 필요하다.

## 7. API 계약

### 7.1 요청

    GET /api/games/{session_id}/objectives

기존 세션 소유권 쿠키를 사용한다.

별도 요청 Body는 필요하지 않다.

### 7.2 기존 응답

    {
      "items": [
        {
          "objectiveId": "OBJ_FIND_CARD_USER",
          "status": "ACTIVE"
        }
      ]
    }

### 7.3 변경 응답

    {
      "items": [
        {
          "objectiveId": "OBJ_FIND_CARD_USER",
          "status": "ACTIVE",
          "chapter": "CH03",
          "title": "임시 카드 사용자 조사",
          "description": "카드 사용 기록과 다른 자료를 비교해 사용자를 좁혀 보세요."
        }
      ]
    }

### 7.4 응답 필드

| 필드 | 자료형 | 필수 여부 | 변경 사항 |
|---|---|---|---|
| objectiveId | string | 필수 | 기존 유지 |
| status | string | 필수 | 기존 유지 |
| chapter | string | 필수 | 신규 추가 |
| title | string | 필수 | 신규 추가 |
| description | string | 필수 | 신규 추가 |

기존 필드를 삭제하거나 자료형을 변경하지 않는다.

기존 필드만 사용하는 프론트엔드와의 호환성을
유지하는 추가형 API 변경이다.

### 7.5 상태값

| 상태 | 응답 포함 여부 | 표시 |
|---|---|---|
| LOCKED | 제외 | 미표시 |
| ACTIVE | 포함 | 진행 중 |
| COMPLETED | 포함 | 완료 |

LOCKED는 내부 상태 계산에 사용되며
프론트엔드 응답에는 포함하지 않는다.

### 7.6 응답 상태 코드

| 상태 코드 | 설명 |
|---|---|
| 200 | 정상 조회 |
| 404 | 세션 없음 또는 소유권 검증 실패 |
| 503 | 목표 규칙 구성 오류 |

기존 오류 응답 계약을 유지한다.

### 7.7 캐시 정책

    Cache-Control: private, no-store

세션별 수사 진행 정보의 캐시 저장을 방지한다.

## 8. 목표 공개 및 완료 조건

기존 objective_status 함수를 그대로 사용한다.

    세션 소유권 검증
          |
          v
    승인된 목표 규칙 확인
          |
          v
    콘텐츠 버전 및 사건 검증
          |
          v
    챕터 해금 여부 확인
          |
          v
    선행 증거 획득 여부 확인
          |
          +-------------------+
          |                   |
          v                   v
        LOCKED           공개 가능
          |                   |
       응답 제외              v
                         완료 조건 평가
                              |
                    +---------+---------+
                    |                   |
                    v                   v
                  ACTIVE            COMPLETED
                    |                   |
                    +---------+---------+
                              |
                              v
                        표시 문구 추가
                              |
                              v
                         API 응답 반환

이전에 해금한 챕터의 목표도 기존 정책에 따라
조회 결과에 포함된다.

목표 조회 과정에서 게임 진행 상태를 변경하지 않는다.

## 9. 구현 상세

### 9.1 표시 문구 카탈로그

OBJECTIVE_DISPLAY_TEXT를 추가하였다.

MappingProxyType을 사용하여 실행 중 표시 문구
매핑의 항목이 임의로 변경되지 않도록 구성하였다.

표시 문구 카탈로그 자체는 목표 공개 권한을
부여하지 않는다.

승인된 목표 규칙과 기존 상태 평가 결과를
모두 통과한 목표에 대해서만 사용한다.

### 9.2 기본 문구 처리

승인된 목표 규칙은 존재하지만 표시 문구가
등록되지 않은 경우 다음 문구를 반환한다.

    title: 수사 목표
    description: 현재 공개된 자료와 인물을 조사하세요.

승인 규칙에 없는 목표를 자동으로 추가하지 않는다.

### 9.3 응답 모델 확장

ObjectiveItem에 다음 필드를 추가하였다.

    chapter: str
    title: str
    description: str

ObjectiveResponse의 items 배열 구조는 유지한다.

## 11. 프론트엔드 연동

기존 ObjectiveItem 인터페이스를 다음과 같이
확장할 수 있다.

    export interface ObjectiveItem {
      objectiveId: string
      status: string
      chapter: string
      title: string
      description: string
    }

목표 카드의 제목에는 title을 사용하고
상세 안내에는 description을 사용한다.

chapter는 목표를 챕터별로 분류할 때 사용한다.

status에 대한 기존 표시 함수를 유지한다.

서버에서 반환하지 않은 목표는
프론트엔드에서 임의로 추가하지 않는다.

기존 백엔드 버전과의 혼용이 필요한 기간에는
신규 필드를 선택적으로 처리하고 기존 기본 문구를
대체값으로 사용하는 것을 권장한다.

이번 이슈에서는 프론트엔드 코드를 수정하지 않았다.
